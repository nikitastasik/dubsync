# dubsync

Перенос звуковой дорожки из одного релиза фильма на картинку другого: берём
видео там, где оно лучше (4K HDR), а озвучку — там, где она лучше (обычно
1080p), попутно вырезая рекламные вставки и убирая рассинхрон.

## Зачем это нужно

Наивный подход — «вырезать рекламу и склеить» — не работает. Два релиза одного
фильма почти никогда не совпадают по времени идеально: помимо рекламных врезок
между ними обнаруживается **плавный дрейф**, когда смещение звука относительно
картинки медленно уходит на секунду-две туда и обратно. Простая склейка по
нескольким точкам даёт рассинхрон, который прекрасно слышно.

Поэтому здесь строится не одно число сдвига, а **функция смещения от времени** —
с разрывами в местах рекламы и плавным ходом между ними. Звук потом читается по
этой функции с интерполяцией, то есть скорость незаметно подстраивается.

## Установка

```bash
pip install -r requirements.txt
```

Нужен `ffmpeg` с `ffprobe` в `PATH` (`brew install ffmpeg`).

## Использование

Посмотреть, какие в файлах есть звуковые дорожки:

```bash
python sync.py --target 4k.mkv --source 1080p.mkv --list-audio
```

Собрать результат:

```bash
python sync.py --target 4k.mkv --source 1080p.mkv --out result.mkv
```

`--target` — файл, чья **картинка** пойдёт в результат. `--source` — файл, чей
**звук** переносим. Полезные ключи: `--source-audio N` (если в источнике
несколько дорожек), `--codec flac` вместо AC3, `--work DIR` (промежуточные
файлы; при повторном запуске переиспользуются, а самая долгая часть —
декодирование видео — не повторяется).

Результат: MKV с видео и всеми дорожками цели плюс новая синхронизированная
дорожка первой и включённой по умолчанию. Главы, субтитры и Dolby Vision
сохраняются.

## Как это работает

1. **Кадры.** Из обоих файлов извлекается поток крошечных кадров (48×27,
   grayscale). Каждый кадр сводится к 32 числам, нормированным внутри кадра —
   так разница HDR/SDR, кодеков и яркости перестаёт мешать, а структура сцены
   остаётся. Отдельно определяются чёрные полосы: один релиз может хранить
   картинку 2.4:1 внутри кадра 16:9, другой — уже обрезанной, и без приведения
   к общей области сопоставление разваливается.
2. **Грубая карта.** По прореженным кадрам ищется путь смещений динамическим
   программированием: скачок стоит фиксированную цену, поэтому карта выходит
   кусочно-постоянной и не пляшет за шумом. Крупные скачки — рекламные вставки.
3. **Границы вставок.** Для каждой вставки перебираются кандидатные точки
   склейки, и для каждой независимо подбирается смещение слева и справа. Верная
   точка — там, где оба куска ложатся одинаково хорошо. Точность — до кадра.
4. **Точная карта.** На полном фреймрейте, в узком коридоре вокруг грубой
   карты, для узлов каждые 5 секунд считается смещение с субкадровой точностью
   (парабола по вершине корреляции), затем сглаживается локальной регрессией.
5. **Сдвиг звука.** Карта построена по картинке. Если в каком-то релизе звук
   смещён относительно видео, это отдельно измеряется по звуку и учитывается.
6. **Рендер.** Звук читается по карте с интерполяцией Catmull-Rom.
7. **Сборка и проверка.** Мукс с `-max_interleave_delta 0`, затем замер
   остаточного рассинхрона и проверка чередования дорожек.

### Две грабли, на которые стоит не наступать

**Чередование дорожек.** Если собрать файл обычным `ffmpeg -c copy`, добавленная
дорожка может лечь с отрывом в **гигабайты** от видео того же момента. Файл при
этом полностью корректен по всем проверкам, но плеер захлёбывается: картинка
сыплется артефактами или замирает, хотя звук идёт. Лечится
`-max_interleave_delta 0` (уже включено в `ff.mux`). Проверка — в
`verify.interleaving`.

**Звук — плохой поводырь.** Когда озвучки разные, корреляция звука шумит на
сотни миллисекунд и уверенно выдаёт ложные пики. Картинка у релизов одна и та
же, поэтому структуру надо брать из видео, а звук использовать только для
финальной проверки и замера сдвига звук/видео.

## Можно ли доверять этому без присмотра

Полностью автоматически проходит всё: поиск вставок, границы, карта, рендер,
сборка, проверка. В конце печатается отчёт (и складывается в
`report.json`) — на него и надо смотреть:

- **качество сопоставления** — медиана должна быть выше ~0.8;
- **границы вставок** — качество слева/справа выше ~0.9, а длина вставки
  правдоподобна (15–40 с для рекламы);
- **остаточный рассинхрон** — медиана в пределах пары десятков миллисекунд,
  доля замеров в пределах 40 мс — 80% и выше;
- **чередование** — худший разброс единицы мегабайт, не гигабайты;
- **стыки** — скачок на склейке не больше обычного перепада рядом.

Чего инструмент не знает и где нужен человек:

- **Разные монтажные версии.** Если релизы отличаются не рекламой, а вырезанными
  сценами (theatrical против unrated), «вставки» найдутся, но это будут куски
  фильма. Проверяйте длину и содержимое — контактный лист по найденным границам
  собирается одной командой ffmpeg.
- **Вырезанный фильм.** Автоматика вставки рекламы иногда заменяет фрагмент
  фильма, а не добавляет время. Тогда звука для этого фрагмента просто нет.
  Признак — точки склейки слева и справа не сходятся.
- **Выбор дорожек.** Какую озвучку из источника брать и что оставлять в
  результате — решение человека.

Время работы — порядка получаса на полнометражный фильм, почти целиком на
декодирование видео (4K HEVC — самая долгая часть). Нужно место под результат
плюс около 3 ГБ на промежуточные файлы.

## Структура

```
sync.py             командный интерфейс
dubsync/ff.py       вызовы ffmpeg/ffprobe, сборка MKV
dubsync/video.py    признаки кадров, определение чёрных полос
dubsync/audio.py    признаки звука
dubsync/corr.py     нормированная корреляция, уточнение пика
dubsync/align.py    грубая карта, границы вставок, точная карта, сглаживание
dubsync/render.py   перекладка звука по карте
dubsync/verify.py   проверки результата
dubsync/pipeline.py оркестровка
research/           черновики исследования, в том числе тупиковые ветки
examples/           данные разбора «Evil Dead Burn» (2026)
```

`research/` — сырые скрипты, которыми задача решалась в первый раз, включая
то, что **не** сработало: разностный канал L−R (микширования релизов не
фазово-совместимы), спектральный поток как признак (обваливает корреляцию),
корреляция сырых отсчётов (мастера фонограмм разные, пик размыт). Оставлены
намеренно — чтобы не пробовать это заново.
